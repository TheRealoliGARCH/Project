# U1--U7 Interface Contract Specification

## 1. Purpose

This document defines the interfaces between the seven verification layers. Passing each U-level test suite is not sufficient to establish composition: every downstream stage must receive an explicitly specified mathematical object from its upstream stage.

The canonical architecture is

$$
U1\xrightarrow{I_{12}}U2\xrightarrow{I_{23}}U3\xrightarrow{I_{34}}U4\xrightarrow{I_{45}}U5\xrightarrow{I_{56}}U6\xrightarrow{I_{67}}U7.
$$

The strengthened epistemic layer is downstream of U7 for now:

$$
U7\xrightarrow{I_{7O}}\mathcal O.
$$

No interface is allowed to silently coerce, reorder, invent, or repair an upstream object.

## 2. Common contract fields

Every interface must specify:

1. **Input object:** exact mathematical type and dimensions.
2. **Output object:** exact mathematical type and dimensions.
3. **Variable ordering:** canonical ordering of vector and matrix components.
4. **Domain:** admissible values and finiteness requirements.
5. **Units/scaling:** interpretation and normalization of numerical quantities.
6. **Invariants:** identities that must survive the interface.
7. **Tolerance:** numerical tolerance where exact equality is impossible.
8. **Determinism:** whether identical inputs must produce identical outputs.
9. **Failure semantics:** invalid inputs must fail explicitly rather than being silently repaired.
10. **Provenance:** whether an output is observed, estimated, simulated, or theoretical.

## 3. I12: U1 algebraic closure to U2

### Required upstream object

U1 produces three-rate symmetric invariants

$$
R=(r_A,r_B,r_C)
$$

from

$$
(r_1,r_2,r_3),
$$

with the associated polynomial

$$
P(\lambda)=\lambda^3-r_A\lambda^2+r_B\lambda-r_C.
$$

### Required downstream object

U2 currently operates on three-Republic financial, political, security, and defense states. Therefore I12 must explicitly define how the U1 rate object maps into the financial component of the U2 state:

$$
I_{12}:R\mapsto r\in\mathbb R^3.
$$

The canonical Republic ordering is

$$
(G,I,T)=(\text{Greece},\text{India},\text{Italy}).
$$

The mapping must preserve the rate values and must not confuse symmetric invariants with the ordered Republic vector. If root recovery is required, the recovered roots must be matched to Republic labels by an explicit labeling rule; permutation invariance alone does not provide labels.

### Audit requirement

**Status: interface gap requiring explicit implementation/test.** U1 verifies algebraic closure, while U2 independently constructs a three-dimensional financial state. The repository must test that an admissible U1 output can enter U2 without ambiguity.

## 4. I23: U2 political-financial-security closure to U3

U2's complete state is

$$
X_2=(r,p,s,g).
$$

U3 requires, for each Republic, output and military allocation:

$$
(Y_i,G_{m,i},T_i,E_i).
$$

The interface must explicitly expose the U2 security/defense state needed by U3 and preserve the Republic ordering. In particular,

$$
G_{m,i}=g_i
$$

must be an explicit mapping if U2's defense variable is the U3 military allocation.

Threat and external-security variables must likewise be explicit rather than inferred from unrelated state components.

### Audit requirement

**Status: mostly specified.** U3 declares itself downstream of U2, but the exact field-level mapping must be tested.

## 5. I34: U3 welfare-warfare optimality to U4

U3 establishes the resource identity

$$
C_i=Y_i-G_{m,i}
$$

and welfare/strategic diagnostics. U4 takes the baseline state

$$
X_{4,i}=(p_i,r_i,s_i,G_{m,i},Y_i).
$$

Therefore I34 must preserve

$$
(p,r,s,g,Y)
$$

and satisfy

$$
C_i=Y_i-G_{m,i}>0
$$

before stress perturbations are applied.

The U3 optimality result is a diagnostic/constraint; U4 must not silently replace the U3 optimum with a different allocation.

### Audit requirement

**Status: strong, with explicit field-level tests still required.**

## 6. I45: U4 stress testing to U5 causal validation

U4 generates stressed states under explicit shocks

$$
(\Delta r_i,\Delta p_i,\Delta s_i,\Delta E_i).
$$

U5 currently works with treatment/control outcomes and causal estimands. Consequently I45 cannot simply pass an undifferentiated stress-test table and call it causal evidence.

A valid interface must distinguish:

- deterministic stress scenarios;
- assigned treatment/intervention variables;
- potential outcomes $Y(1),Y(0)$;
- observed outcomes;
- control variables/confounders;
- causal assumptions.

Thus the interface must be represented schematically as

$$
I_{45}:
(\text{stress design},\text{state response})
\mapsto
(\text{treatment},\text{outcome},\text{design metadata}),
$$

and must never infer exogeneity merely because a shock was generated by the stress harness.

### Audit requirement

**Status: conceptual gap.** An explicit design contract is required before U4 output can be interpreted by U5 as causal input.

## 7. I56: U5 causal/identification validation to U6 global uniqueness

U5 produces estimands, uncertainty quantities, posterior quantities, and deterministic identification diagnostics. U6 requires a complete equilibrium map

$$
T:\mathcal X\to\mathcal X
$$

and a contraction certificate

$$
\sup_{x\in\mathcal X}\|DT(x)\|_\infty<1.
$$

Therefore I56 must not equate statistical identification with mathematical uniqueness. It must pass the identified parameter/state restrictions as constraints or metadata into U6 while retaining their epistemic status.

A proposed interface is

$$
I_{56}:
(\text{identified restrictions},\text{uncertainty},\text{provenance})
\mapsto
(\mathcal X,T,\text{admissibility metadata}).
$$

### Audit requirement

**Status: conceptual gap.** The repository currently separates U5 and U6 correctly but does not yet specify a field-level computational hand-off.

## 8. I67: U6 uniqueness to U7 integrated validation

U6 provides a fixed-point map, admissible domain, and sufficient uniqueness certificate. U7 consumes ordered stage outputs.

The U6 output must therefore include at least:

$$
(x^*,\mathcal X,T,b,\text{certificate status}),
$$

where $b<1$ is the declared Jacobian bound when uniqueness is certified.

U7 must preserve the distinction between:

- existence of a computed fixed point;
- local stability;
- sufficient global uniqueness certification.

### Audit requirement

**Status: strong.** U7's contract model already requires stage outputs to satisfy declared contracts before proceeding.

## 9. I7O: U7 to observational recoverability

The strengthened theory defines

$$
\mathcal E^\star(S)=\mathcal E_0\cap\mathcal O(S),
$$

and an observation model

$$
S=\mathcal H(X)+\varepsilon.
$$

U7 currently establishes deterministic computational integration. It does not yet establish that the integrated state is observationally recoverable.

The future interface must pass the integrated equilibrium and the observation specification into an observation layer:

$$
I_{7O}:(x^*,\mathcal H,S)\mapsto\mathcal E^\star(S).
$$

Recoverability should then be tested through observational equivalence, local Jacobian rank, and/or a global injectivity criterion appropriate to the specified model.

### Audit requirement

**Status: new interface.** Do not add it to U7 until the observation model is operationally specified.

## 10. Interface invariants

Across the entire chain the following invariants are mandatory:

### Sovereign dimensionality

$$
N=3
$$

throughout the Greece--India--Italy implementation.

### Ordering

$$
(G,I,T)
$$

must have one canonical meaning at every interface.

### Finiteness

All computational state components must be finite. NaN and infinite values are invalid states.

### Provenance

Observed data, estimates, simulations, forecasts, and theoretical quantities must remain distinguishable.

### No silent coercion

An interface failure must terminate the downstream computation rather than silently converting dimensions, filling missing values, or reordering variables.

### Numerical semantics

Exact algebraic identities must not be weakened into approximate tests merely for convenience. Numerical tolerances apply only where floating-point computation genuinely requires them.

## 12. Completion criterion

The U1--U7 interface audit is complete only when every interface has:

1. a documented mathematical contract;
2. a canonical data structure;
3. deterministic validation tests where applicable;
4. explicit failure semantics;
5. provenance preservation;
6. at least one end-to-end test demonstrating that the downstream stage consumes the upstream object actually produced by the preceding stage.

A green unit-test suite without these interface properties is insufficient evidence of architectural closure.
